# Wonderlog — Deep Audit 2026-10-06

Baseline audited: `main @ c6cff63b3db085af5a17ac87a10f96c0d8935c35`

Scope:
- Flutter architecture and runtime wiring;
- E2 Ecosystem UX Completion;
- Journey / Memory / Album / Capture;
- Smart Journey / Map Memories / Rediscover;
- Premium / RevenueCat;
- Supabase identity / cloud backup;
- localization, release engineering and repository hygiene.

## Executive verdict

The Flutter baseline is structurally solid enough to continue development and E1 remains a
valid CERTIFIED GOLDEN interoperability primitive. MAXI STEP E2 is implemented and its PR
gate passed analyze, tests, Web release, APK and AAB.

The whole Wonderlog product is **NOT production-certified yet**. The main remaining risk is
not the E1/E2 bridge itself, but feature parity and release truthfulness around Premium,
cloud backup, offline maps, media UX, migration and deployment.

## P0 — Release blockers

### 1. Premium enforcement is inconsistent and bypassable

Evidence:
- `showCreateJourneyDialog()` creates Journeys directly without `PremiumGate`.
- Journey detail opens `MemoryEditorPage` directly, so normal Memory creation bypasses
  the free-memory limit.
- Capture applies the Memory limit per Journey.
- E2 currently calls `canCreateMemory()` using the total global Memory count, even though
  `SubscriptionConfig.freeMemoriesPerJourney` is explicitly per Journey.

Impact:
- free limits can be bypassed in normal UI;
- E2 can incorrectly block a user after five Memories globally;
- entitlement behavior differs by entry point.

Required repair:
- one canonical creation policy for Journey / Memory / Album;
- all entry points use the same service;
- define an explicit policy for unassigned/free Memories instead of reusing the per-Journey
  limit ambiguously;
- add cross-entry-point entitlement tests.

### 2. Cloud backup / restore exists as code but is not wired into the runtime

Evidence:
- `CloudSyncRepository`, `DriftCloudLocalDataSource`,
  `SupabaseCloudProvider` and `CloudRestoreRepository` exist;
- code search shows no production construction/use of these services from `main.dart`;
- `syncNow()` has no production caller;
- `restoreEverything()` is only exercised by tests;
- the main controller wires identity and RevenueCat, but not the cloud sync pipeline.

Impact:
- Premium UI advertises secure cloud backup/restore while the application runtime does not
  expose a functioning backup workflow.

Required repair:
- wire cloud services behind authenticated + Premium guards;
- explicit backup settings UI;
- queue local mutations;
- manual Sync Now / Restore;
- background policy only after deterministic manual sync is certified;
- do not market cloud backup as shipped until the runtime path is verified.

### 3. Offline Maps is advertised but not implemented as an offline map system

Evidence:
- `OfflineMapRegion` and CRUD metadata exist;
- `watchOfflineRegions()` / `saveOfflineRegion()` have no product-side callers;
- the map still renders tiles from
  `https://tile.openstreetmap.org/{z}/{x}/{y}.png`;
- there is no tile download/cache region engine in the repo;
- Premium page lists Offline Maps as a benefit.

Impact:
- the current Premium claim exceeds the implemented capability.

Required repair:
- either remove/disable the Premium claim for now, or implement a real offline tile region
  manager with quota/storage/eviction/status and offline tile provider.

### 4. Drift schema v9 migration is not yet certified on existing user data

E2 changed `memories.tripId` / `journeyId` to nullable and added inbox outcome columns.
The migration uses Drift `TableMigration` to preserve rows.

Current CI proves fresh-schema generation and tests, but not:
- Room v6 -> Drift v9 on a real legacy database;
- Drift v8 -> v9 with existing ecosystem rows;
- preservation of Memory/Photo/Attachment relations during the table rewrite.

Required repair:
- deterministic fixture migration tests;
- physical upgrade test on a copy of an actual legacy DB;
- backup-before-cutover evidence;
- only then mark the database migration CERTIFIED.

### 5. Localizations are incomplete

Final E2 PR CI still reports **48 untranslated messages** for each of:
- de
- es
- fr
- it
- pt

The build succeeds because Flutter falls back, but product localization is not complete.

Required repair:
- close all untranslated keys;
- make untranslated-message count a release gate.

## P1 — Major product gaps

### 6. Media is stored, but core UI often does not render the actual photos

Journey Album and Memory Detail currently render icons/file names rather than real
thumbnails/images in the examined primary surfaces.

Impact:
- a travel diary can import photos but the core browsing experience is still below product
  parity.

Required repair:
- platform-safe local image widget;
- thumbnail rendering;
- full-screen viewer;
- missing/corrupt file fallback;
- delete/favorite/cover operations;
- memory-linked gallery.

### 7. Keepsakes/Documents can be imported but are not meaningfully consumable

Memory Detail lists attachment metadata, but the examined list tiles have no open/share
action.

Required repair:
- open document with platform handler;
- share/export;
- delete with confirmation;
- file-not-found handling.

### 8. Journey / Memory / Photo delete/archive/edit UX is incomplete

Repository delete methods exist, but normal product surfaces do not expose a consistent
user flow for delete/restore/archive. Journey editing is also not represented as a complete
product flow in the audited primary screens.

Required repair:
- edit Journey;
- archive/unarchive Journey;
- delete Journey with cascade preview;
- delete Memory;
- unlink/delete Photo;
- confirmations and undo where appropriate.

### 9. E2 can double-materialize on rapid/concurrent action

E2 checks `item.isPending` on the in-memory object, then creates domain data, then updates
the inbox row. The inbox resolution write is not an atomic "claim if still pending".
The UI action buttons are not globally locked by a per-item busy state.

Impact:
- two rapid taps / concurrent operations can create duplicate Memories or Journeys before
  the inbox row is resolved.

Required repair:
- atomic claim/resolve state or compare-and-set update;
- per-item busy state in UI;
- concurrency test proving exactly-once materialization.

### 10. E2 photo handoff is metadata-safe but binary-incomplete

E1 intentionally certifies safe media metadata with omitted binary handoff. Therefore an
Anna photo can arrive as an ecosystem item, but E2 cannot reconstruct the original binary
photo unless a certified media transport exists.

Required repair:
- explicit binary handoff protocol later;
- until then, UI must clearly distinguish "photo metadata received" from "photo imported".

### 11. Free/unassigned Memory has no first-class library surface

E2 correctly introduces `journeyId = null` instead of a fake Journey. Search can find the
Memory and Inbox history can reopen it, but there is no dedicated global Memories library
for immediate everyday browsing.

Required repair:
- global Memories surface/filter for "Unassigned";
- assign/move to Journey later;
- preserve provenance from ecosystem imports.

### 12. Map "route" is a chronological straight polyline, not road routing

`JourneyRouteBuilder` orders clusters by timestamp and the map draws a `Polyline` between
coordinates. It does not route along roads/trails.

Required repair:
- keep this only if labelled as a replay/path approximation;
- otherwise integrate an actual routing provider with explicit offline/online behavior.

## P2 — Architecture, performance and maintainability

### 13. Dead/duplicated Journey repository — RESOLVED IN STEP 23

`DriftJourneyRepository` was confirmed to be referenced only by its own test, while
production uses `DriftWonderlogRepository`, which already implements
`JourneyRepository`.

Step 23 removed the duplicate implementation and retargeted the repository test to the
production repository. The `JourneyRepository` domain interface remains in use and is not
dead code.

### 14. N+1 database reads in Memory-with-Photos streams

`watchMemoriesWithPhotos()` loops Memories, then separately queries links, photos and
attachments for each Memory.

Impact:
- avoidable latency for large Journeys.

Required repair:
- Drift joins/batched queries and deterministic performance test.

### 15. Global search is O(n) on every keystroke

Search watches all Journeys and all Memories and re-runs an in-memory normalized contains
scan on each `onChanged`.

This is functionally correct for small data but will scale poorly.

Required repair:
- debounce;
- FTS/indexed search once dataset thresholds justify it.

### 16. Rediscover Memory photo association can be imprecise

`RediscoverDataAdapter.memories()` derives a photo from photos sharing the same
`journeyId`, rather than from the Memory-to-Photo relationship.

Impact:
- a Memory card can display an unrelated photo from the same Journey.

Required repair:
- feed Rediscover the real MemoryPhoto links or a `MemoryWithPhotos` projection.

### 17. OSM search is fixed to English

`OpenStreetMapRepository.acceptLanguage = 'en'` regardless of selected app/device locale.

Required repair:
- inject locale dynamically;
- keep cache keys locale-aware.

## Release engineering / delivery gaps

### 18. Standard CI produces a large universal APK

Final E2 PR CI produced:
- APK: about **73.5 MB**
- AAB: about **69.7 MB**

The previously tested ARM64-only ecosystem build was roughly 25 MB.

Required repair:
- standard test APK should be ARM64/split-per-ABI where appropriate;
- AAB remains the Play distribution artifact;
- keep universal APK only when explicitly needed.

### 19. Web is built but not deployed to a stable URL

The only workflow builds and uploads a Web artifact. There is no GitHub Pages / hosting
deployment workflow.

This does not yet meet the project standard of a stable PC-verifiable Web preview.

### 20. iOS is generated but not built

CI creates the iOS shell on Linux but has no macOS/iOS build job.

### 21. Production signing is not configured in repository CI

The workflow regenerates Android platform files and does not contain a production signing
configuration. The CI APK is valid as a verification artifact, not evidence of Play-ready
release signing.

### 22. Version metadata is stale

`flutter/pubspec.yaml` still reports `0.1.0+1`, which no longer describes the maturity of
the current baseline.

### 23. Documentation has drifted behind reality

At the audited commit:
- README still describes E1 as not cross-app certified;
- ROADMAP still lists the official Ecosystem Inbox as "LATER" despite E2 being merged;
- FLUTTER_MIGRATION still refers to Drift v8 and candidate Golden state.

### 24. Repository contains a large donor ZIP

`wanderlog-memories (2).zip` is about 5.39 MB and is the largest blob in the repository.
It may remain useful as donor evidence, but it should not remain indefinitely as an opaque
binary in the main source history if a better archival location is available.
